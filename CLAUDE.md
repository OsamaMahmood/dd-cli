# CLAUDE.md

Always-loaded context for `dd-cli`. Skim this in full, then jump to the right [`.claude/`](.claude/) doc for whatever you're doing.

## What this is

`dd-cli` is a Python CLI (`dd`) for managing [DefectDojo](https://www.defectdojo.org/), an open-source vulnerability-management platform. Two audiences:

- **CI/CD pipelines** uploading scanner output (Trivy, Bandit, Semgrep, etc.) into DefectDojo. Drop-in replacement for the archived [`dd-import`](https://github.com/MaibornWolff/dd-import) — every legacy `DD_*` env var and the `dd-reimport-findings` / `dd-import-languages` console scripts keep working unchanged.
- **Operators** doing day-to-day DefectDojo work — `dd findings list --severity Critical`, `dd findings close 42 --note "fixed"`, `dd engagements close 12`, etc.

License: BSD-3-Clause. v2.0.0 shipped 2026-05-07. Single maintainer ([@OsamaMahmood](https://github.com/OsamaMahmood)).

## Hard rules

1. **Don't edit `src/dd_cli/_client/`** — it's generated by `openapi-python-client` from [`dd-api.json`](dd-api.json). Regenerate via `make generate-client`. The path is excluded from ruff, mypy, and coverage on purpose.
2. **Don't change legacy stdout/stderr/exit codes** in [src/dd_cli/cli/legacy.py](src/dd_cli/cli/legacy.py) without a corresponding compat-test failure. CI pipelines in production rely on the exit-1-on-any-failure contract.
3. **No emojis in source or docs**, with one deliberate exception: `cli/legacy.py` keeps `❌` `✅` `📋` `🚀` to match upstream `dd-import` stdout — compat tests assert the strings.
4. **Comments explain WHY, never WHAT.** Many modules ship without inline comments at all. If the code is self-explanatory, leave it alone. See [.claude/conventions.md](.claude/conventions.md).
5. **Tag releases only from a commit reachable from `origin/main`.** `release.yml` has a guard that fails the build otherwise — added after [v0.4.0 shipped with an empty changelog](RELEASING.md) because the tag was placed on a stale feature branch.

## The pattern you'll touch most

Each DefectDojo resource (products, findings, engagements, …) lives in one file under [src/dd_cli/cli/](src/dd_cli/cli/) and follows this shape:

```python
# src/dd_cli/cli/products.py — full file is ~100 lines
PRODUCTS_SPEC = ResourceSpec(
    name="product", plural="products",
    path="/api/v2/products/",
    columns=("id", "name", "prod_type", "business_criticality", "lifecycle"),
)
products_app = typer.Typer(name="products", ...)

@products_app.command("list")
def products_list(ctx, name=None, prod_type=None, ...):
    list_resource(ctx, PRODUCTS_SPEC, filters={...}, ...)

@products_app.command("get")
def products_get(ctx, product_id=None, name=None, ...):
    get_dispatch(ctx, PRODUCTS_SPEC, resource_id=product_id, name=name, ...)

register_crud(products_app, PRODUCTS_SPEC)  # adds create/update/delete/edit
```

`register_crud` and the `list_resource` / `get_dispatch` helpers live in [src/dd_cli/cli/_resource.py](src/dd_cli/cli/_resource.py). Action verbs (`dd findings close`, `dd users deactivate`, etc.) are added per-module on top of the generic CRUD.

## Setup quick path

```bash
git clone https://github.com/OsamaMahmood/dd-cli.git
cd dd-cli
make install-dev          # pip install -e ".[dev,test]"
make lint && make typecheck && make test
```

`make install-all` adds the `docs` and `client-gen` extras (only needed if you're touching docs or regenerating the API client).

Default `make test` runs **unit + snapshot + compat** suites (~257 + 12 + 9 tests, ~20s). Integration tests are gated behind `make smoke` and require a live DefectDojo (`DD_URL` + `DD_API_KEY`).

## Common gotchas (one-liners; details in the linked docs)

- **`tests/test_cli_resources.py` covers the read-side resource commands; `tests_cmd.py` (note `_cmd` suffix) is the CLI module for `dd tests`** — naming collision with pytest's `tests_*.py` discovery. Don't rename. ([.claude/testing.md](.claude/testing.md))
- **Docker Hub namespace is `m4rkm3n/dd-cli`, not `osamamahmood/dd-cli`** — different from the GitHub handle. GHCR uses `osamamahmood`. ([.claude/release.md](.claude/release.md))
- **`v2.0.0-rc.1` (tag) becomes `2.0.0rc1` (PEP 440)** — release.yml uses `packaging.version.Version()` to compare canonical forms. Don't string-compare tag vs wheel version. ([.claude/release.md](.claude/release.md))
- **DefectDojo's findings-create has an undocumented required field `found_by`** (array of test_type IDs). There's a dedicated test pinning the error message. ([.claude/domain.md](.claude/domain.md))
- **`DD_CLI_*` env vars take precedence over `DD_*`** because of `AliasChoices` ordering in pydantic-settings. Both are honored; new code should prefer `DD_CLI_*`. ([.claude/compatibility.md](.claude/compatibility.md))

## Commit + PR style

- Conventional Commits: `feat(cli):`, `fix(client):`, `docs:`, `chore:`, `test:`, `refactor:`. Scope is optional but preferred.
- One logical change per PR.
- The "Test plan" section of a PR description is a checkbox list the reviewer walks through. Include realistic local-validation steps.
- **Don't add a `Co-Authored-By: Claude` trailer** — the maintainer doesn't want one.
