# Conventions

Style, naming, and "the way we write code" rules for `dd-cli`. Read this before opening a PR. Most rules exist because of a specific past failure or constraint — those are called out so you can judge edge cases instead of memorizing.

## Project layout

`dd-cli` uses **src layout** — package source is at `src/dd_cli/`, never installed implicitly. `pip install -e .` is the only way to make `import dd_cli` work in development.

Top-level layout (only what you'll touch):

```
dd-cli/
├── src/dd_cli/
│   ├── cli/                 # Typer commands; one module per resource
│   │   ├── _resource.py     # generic CRUD helpers — read this before adding a new resource
│   │   ├── app.py           # root Typer + main() entry point
│   │   ├── legacy.py        # dd-reimport-findings / dd-import-languages shims
│   │   ├── import_cmd.py    # the new `dd import findings|languages` command
│   │   ├── config_cmd.py    # `dd config get/set/list/use`  (note: _cmd suffix)
│   │   ├── tests_cmd.py     # `dd tests` CLI            (note: _cmd suffix)
│   │   ├── ping.py
│   │   ├── configure.py
│   │   └── <resource>.py    # products, findings, engagements, users, etc. — 14 modules
│   ├── _client/             # GENERATED — see "Generated code boundary" below
│   ├── _version.py          # build-time generated by hatch-vcs; gitignored
│   ├── client.py            # DefectDojoClient (HTTP wrapper)
│   ├── config/              # Profile, Config, load_profile, paths, legacy_env
│   ├── errors.py            # DDCliError hierarchy + exit codes
│   ├── output/              # table / json / yaml renderers
│   ├── workflows/           # import_findings, import_languages
│   └── version.py           # __version__ shim that reads from package metadata
├── tests/                   # see .claude/testing.md
├── docs/                    # mkdocs-material site
└── dd-api.json              # DefectDojo OpenAPI spec; source of truth for _client/
```

## Naming

| Thing | Convention | Example |
|---|---|---|
| Resource module | lower_snake plural | `products.py`, `risk_acceptances.py`, `dojo_groups.py`, `finding_templates.py` |
| Resource sub-app variable | `<plural>_app` | `products_app`, `findings_app`, `risk_acceptances_app` |
| ResourceSpec constant | `<RESOURCE>_SPEC` | `PRODUCTS_SPEC`, `FINDINGS_SPEC` |
| Command function | `<plural>_<verb>` | `products_list`, `products_get`, `findings_close` |
| Module that collides with stdlib/pytest | `<name>_cmd.py` | `tests_cmd.py` (avoids pytest's `tests_*.py` discovery), `config_cmd.py` (avoids the `config/` package) |
| Typed errors | `<Name>Error` ending | `AuthError`, `NotFoundError`, `ValidationError`, `APIError`, `NetworkError`, `ConfigError` |
| Workflow class | `<Name>Workflow` | `ImportFindingsWorkflow`, `ImportLanguagesWorkflow` |
| Workflow options | `<Name>Options` | `ImportFindingsOptions`, `ImportLanguagesOptions` |
| Generic CRUD command (registered by `register_crud`) | leading underscore | `_create`, `_update`, `_delete`, `_edit` |

**The `_cmd` suffix is load-bearing.** `tests_cmd.py` is not a test file — it's the CLI module for `dd tests`. ruff's `pytest-style` rules (`PT`) trigger on filenames matching `tests_*.py`, so `pyproject.toml` has a per-file ignore: `"**/tests_cmd.py" = ["PT"]`. **Don't rename either `_cmd` file** — you'd either reintroduce the false-positive ruff failures or shadow the stdlib `config` package.

## Imports

- `from __future__ import annotations` at the top of every source file. Lets us write modern type syntax (`int | None`, `list[str]`) without 3.11+ runtime cost.
- Standard library → third-party → first-party (`dd_cli.*`). Ruff's `I` (isort) rule enforces this.
- `from dd_cli.cli._resource import (DEFAULT_LIMIT, ResourceSpec, get_dispatch, list_resource, register_crud)` — multi-line parenthesised imports are normal here; ruff format keeps them tidy.
- Typing: `Annotated[T, typer.Option(...)]` for CLI flag types — Typer reads the `typer.Option` from the annotation.

## Comments

**Default to writing no comments.** Many modules ship without inline comments at all.

Add a comment **only** when the *why* is non-obvious:
- A hidden constraint (e.g. "DefectDojo's `/reimport-scan/` requires multipart even with no file")
- A subtle invariant (e.g. "`AliasChoices` order matters: first wins, so `DD_CLI_*` precedes `DD_*`")
- A workaround for a specific bug or upstream quirk (e.g. "filter out `pro` and `message` keys — DefectDojo Pro upsell")
- Behavior that would surprise a future reader

Don't:
- Explain what the code does ("loop over items"). Self-explanatory code doesn't need a comment.
- Reference the current task or fix ("added for the M4b shim"). That belongs in the PR description and rots as the codebase evolves.
- Write multi-paragraph docstrings. Module docstrings are short — typically 3–10 lines stating the module's purpose.

Examples of good WHY comments from this repo:

```python
# src/dd_cli/client.py
# httpx requires a non-empty `files` dict to switch to multipart;
# pass an empty placeholder when no actual file is provided.

# src/dd_cli/cli/_resource.py
# `tests_cmd.py` triggers ruff's pytest-style rules because the file name
# matches `tests_*.py`. This is CLI code for `dd tests`, not a test module.

# .github/workflows/release.yml
# Tags with a `-` (e.g. v1.0.0-rc.1) are prereleases — never marked
# latest. Stable tags get --latest=true explicitly so GitHub doesn't
# fall back to the publishedAt-time heuristic that left v0.2.0
# incorrectly tagged as Latest after a backfill.
```

## Emojis

**No emojis** in source code, docstrings, or test fixtures.

**One deliberate exception**: [src/dd_cli/cli/legacy.py](../src/dd_cli/cli/legacy.py) keeps `❌` `✅` `📋` `🚀` to match the upstream `dd-import` stdout exactly. CI pipelines that grep for these strings keep working. Compat tests (`tests/compat/test_legacy_entry_points.py`) **assert** the strings:

```python
assert "AUTO-CREATE" in captured.out
assert "Import completed successfully" in captured.out
```

If you find yourself wanting to use an emoji somewhere else, you don't.

## Pydantic conventions

- **`extra="forbid"`** for persisted/user-supplied shapes — `Profile`, `Config`. Catches typos in `~/.config/dd-cli/config.toml` early instead of silently dropping fields.
- **`extra="ignore"`** for env-driven settings — `_EnvOverrides`, `ImportFindingsOptions`, `ImportLanguagesOptions`. The user's shell has hundreds of unrelated vars; we don't want to fail on every one.
- **`SecretStr`** for tokens — `Profile.api_key`. Masked in `dd config show` unless `--show-secrets`. Always call `.get_secret_value()` when handing it to httpx.
- **`AliasChoices(new, old)`** when both new (`DD_CLI_*`) and legacy (`DD_*`) env vars apply. **Order matters: first listed wins.** `DD_CLI_*` always precedes `DD_*`. See [.claude/compatibility.md](compatibility.md).
- **Frozen dataclasses, not pydantic, for in-memory descriptors** that don't need validation or serialization — e.g. `ResourceSpec(frozen=True)`. Cheaper at instantiation; immutability prevents accidental mutation across resource modules.

## Config precedence

Hard-coded order, later wins:

1. Built-in defaults (`Profile()` field defaults)
2. Profile entry in `~/.config/dd-cli/config.toml` (or `$DD_CLI_CONFIG_DIR/config.toml`)
3. `DD_*` environment variables (legacy contract)
4. `DD_CLI_*` environment variables (new names; precede `DD_*` via `AliasChoices` ordering)
5. Explicit CLI flags (passed by Typer to the command function)

If you add a new config field, update this list and add a unit test in [tests/test_config.py](../tests/test_config.py) that proves precedence with mocked layers.

## Write commands — the `--dry-run` / `--yes` / `--from-file` pattern

Every write command (create, update, delete, edit, action verbs) supports a uniform safety surface:

- **`--from-file PATH.{json,yaml}`** — base payload from a file. JSON or YAML (auto-detected by extension).
- **`--field key=value`** (repeatable) — overlay individual fields on top of the file. Values are JSON-parsed first (so `--field prod_type=2` becomes `int 2`, not `str "2"`); falls back to plain string.
- **`--dry-run`** — print the request that would be sent and exit. **Zero HTTP must be made.** This is enforced by `pytest-httpx` failing tests on any unmocked request — see [test_cli_action_verbs.py](../tests/test_cli_action_verbs.py).
- **`--yes` / `-y`** — skip the destructive-op confirmation prompt. Required for use in CI and scripts. Confirmation otherwise prints a `typer.confirm(...)` prompt; declining exits 0.

Don't reinvent these per-command. Use the `_resource.py` helpers:

```python
# in your action verb command body
if dry_run:
    print_dry_run("POST", target, payload, ctx, output)
    return
confirm_or_abort(f"Close finding {finding_id}?", yes=yes)
```

## Read commands — the `--limit` / `--all` / `--output` pattern

Every list command supports:

- **`--limit N`** (default 50) — cap rows. Rendered first N items; further pagination not requested.
- **`--all`** — stream every page from DefectDojo. Overrides `--limit`.
- **`--output table|json|yaml`** (or `-o`) — global flag, can be set on the root or any sub-command. Inherited via `ctx.obj["output"]`.
- **Resource-specific filters** — `--name`, `--severity`, `--product`, etc. Filter values are passed through to httpx as query params; `None` values are dropped, `bool` values are coerced to `"true"`/`"false"`.

## Lint, format, type — what runs and where

`make lint`, `make format`, `make typecheck` run the actual commands. Source of truth: `pyproject.toml`.

### Ruff

```toml
[tool.ruff]
line-length = 100
target-version = "py311"
src = ["src", "tests"]
extend-exclude = ["src/dd_cli/_client", "src/dd_cli/_version.py", "dd_import"]

[tool.ruff.lint]
select = ["E", "W", "F", "I", "B", "UP", "N", "SIM", "RUF", "C4", "PT", "TID"]
ignore = ["E501"]   # line-too-long; the formatter handles it
```

The selected rule families:
- **E, W** — pycodestyle errors and warnings.
- **F** — pyflakes (undefined names, unused imports).
- **I** — isort.
- **B** — flake8-bugbear (`mutable default arg`, etc.).
- **UP** — pyupgrade (use `int | None`, not `Optional[int]`).
- **N** — pep8-naming.
- **SIM** — flake8-simplify (collapse nested ifs, etc.).
- **C4** — comprehensions (prefer generator expressions where appropriate).
- **PT** — pytest-style.
- **TID** — tidy imports (no relative imports beyond the immediate package).
- **RUF** — ruff-specific.

Per-file exceptions:

```toml
[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101"]              # allow `assert` in tests
"**/tests_cmd.py" = ["PT"]         # filename collides with pytest discovery — see Naming
```

`make format` runs `ruff check --fix && ruff format`. Run it before every commit.

### Mypy

```toml
[tool.mypy]
python_version = "3.11"
strict = true
warn_unreachable = true
warn_redundant_casts = true
warn_unused_ignores = true
exclude = ["src/dd_cli/_client/", "dd_import/", "unittests/", "build/", "dist/"]

[[tool.mypy.overrides]]
module = "dd_cli._client.*"
ignore_errors = true
```

`--strict` covers all our code; the generated client is excluded twice (path + module override) because it ships with attrs-style stubs that don't match our pydantic style. **Don't try to "fix" mypy warnings inside `_client/`** — they're suppressed on purpose.

### Pytest

```toml
[tool.pytest.ini_options]
addopts = ["-ra", "--strict-markers", "--strict-config", "-m", "not integration", ...]
markers = [
    "integration: tests that require a live DefectDojo instance",
    "compat: backward-compatibility tests for the dd-import contract",
]
```

`--strict-markers` means a typo in `@pytest.mark.foo` is a hard error. `-m "not integration"` is the default — integration tests need a real DD, run via `make smoke`.

See [.claude/testing.md](testing.md).

## Generated code boundary

[src/dd_cli/_client/](../src/dd_cli/_client/) is the output of `openapi-python-client` against [dd-api.json](../dd-api.json).

- **Vendored** (committed to the repo) so installs work offline and PRs are greppable for endpoint shapes.
- **Excluded** from ruff (`extend-exclude`), mypy (`exclude` + module-level `ignore_errors`), and coverage (`omit`).
- **Never edit by hand.** Regenerate via `make generate-client` after updating `dd-api.json`. See [.claude/workflows.md](workflows.md).
- Uses **attrs**, not pydantic. Both `attrs>=23.2` and `python-dateutil>=2.9` are runtime deps because of this.
- The high-level wrapper [client.py](../src/dd_cli/client.py) mostly bypasses the generated per-endpoint functions — it uses `client.raw.get_httpx_client().<method>(...)` directly. The typed endpoints are verbose and rarely worth the boilerplate over a path string.

## File payload format (`--from-file`)

Both JSON and YAML are accepted; the suffix decides:

```python
# src/dd_cli/cli/_resource.py:_load_payload_file
data = yaml.safe_load(text) if suffix in {".yaml", ".yml"} else json.loads(text)
```

The file must contain a JSON/YAML **object** at the top level — `["foo"]` is rejected with `ValidationError("... must contain a JSON/YAML object, got list")`.

## Field value coercion (`--field key=value`)

```python
# _parse_field
key, _, value = raw.partition("=")
try:
    return key, json.loads(value)        # ints, floats, bools, null, arrays, objects
except json.JSONDecodeError:
    return key, value                    # plain string fallback
```

So `--field active=true` → `{"active": True}`, `--field name=Foo` → `{"name": "Foo"}`, `--field tags=["a","b"]` → `{"tags": ["a", "b"]}`.

## Logging

[structlog](https://www.structlog.org/) is in the dependency list (`structlog>=24.1`) and reserved for future verbose-mode telemetry. Today's commands use `typer.echo()` for normal output and the `Console`/`err_console` Rich consoles in [cli/app.py](../src/dd_cli/cli/app.py) for typed error rendering. **Don't add `print()` calls** — use `typer.echo` (respects Typer's stream redirection) or the consoles.

## When you genuinely need to break a convention

1. **Look in `.claude/decisions.md` first.** If a previous trade-off explains why the convention exists, read it.
2. **Run the compat suite** (`pytest -m compat`) and the snapshot tests (`make test`) — many "small refactors" silently break the legacy contract. CI will catch you, but locally is faster.
3. **Open a focused PR** describing the deviation in the PR body. Don't slide style changes in alongside feature work.

## Pre-commit checklist

Before pushing:

```bash
make format          # ruff --fix + format
make lint            # ruff check + format --check
make typecheck       # mypy --strict
make test            # pytest (unit + snapshot + compat)
```

If you touched docs:

```bash
make docs            # mkdocs build --strict — fails on broken links / missing pages
```

If you touched the API client:

```bash
make generate-client # regenerate _client/ from dd-api.json
make typecheck       # ensure call sites still type-check
```
